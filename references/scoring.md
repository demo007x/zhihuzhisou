# 评分与加权细则（scoring）

> 本文件定义「候选池 → top 20~30 可信素材」的自动打分与加权规则。
> 全程**无人参与**：Agent 在检索后自动执行，人只负责给问题、看最终答案。

---

## 一、目标

从候选池（约 50~100 条）中，自动、稳定、可复现地选出 top 20~30 条「高价值素材」，供后续推理与成稿。

核心原则：**不彻底排除软文，只降权保留**（软文里可能藏真实信号，如"某软件已停更"）。

---

## 二、打分方式：客观字段锚定 + LLM 判断混合

单条得分 = 四个维度加权求和，再乘以软文惩罚系数。

### 权重分配（已定）

| 维度 | 权重 | 谁算 | 说明 |
|---|---|---|---|
| 相关性 | 40% | LLM | 是否真正回答了用户子问题 |
| 可信度 | 25% | 规则（客观） | AuthorityLevel + 能否溯源 |
| 信息量 | 20% | LLM | 有无真实样本 / 数据 / 代价 |
| 传播信号 | 15% | 规则（客观） | VoteUpCount，但不迷信 |

客观维度（可信度 + 传播）合计 40%，保证分数有锚、可复现；LLM 维度（相关性 + 信息量）合计 60%，保留智能判断。

---

## 三、各维度如何算

### 1. 相关性（40%，LLM）
LLM 判断「这条内容是否真正回答了用户的子问题」，给 0~1 分。
- 硬约束词（如"跨平台"）必须严格匹配：词典类 / 单平台独占类内容 → 相关性给低分。
- 只沾边、答非所问 → 低分；切中要害 → 高分。

### 2. 可信度（25%，规则）
```
可信度分 = (AuthorityLevel / 4) × 0.7  +  可溯源加分 0~0.3
```
- AuthorityLevel：1~4，除以 4 归一化（占 0.7）。
- 可溯源加分：有真实 Url 且可点回 → +0.3；无链接 → +0。

### 3. 信息量（20%，LLM）
LLM 判断「有无真实样本 / 数据 / 具体代价」，给 0~1 分。
- 空话套话、泛泛而谈 → 低分；有实测、有数字、有踩坑 → 高分。

### 4. 传播信号（15%，规则）
```
传播分 = log10(VoteUpCount + 1) / log10(1000 + 1)   （封顶 1.0）
```
- 用对数压缩，避免"高赞碾压低赞"：0 赞≈0，10 赞≈0.35，100 赞≈0.67，1000 赞≈1.0。
- **不迷信赞同数**：低赞的"真实体感"可能与高赞营销文同等或更高（由相关性/信息量兜底）。

### 5. 软文惩罚（乘法，不归零）
命中软文特征 → 总分 ×0.4（掉下去但不清零）。
软文特征（命中任一条即触发）：
- 标题极度夸张（"月入5000不是问题""终极解决方案""全网最强"等）
- 正文带带货/引流话术（"加我""找我""学员""报课""免费下载链接"）
- 作者为矩阵号/内容农场（如 `gitblog_00xxx`、批量同质化标题）
- 同源批量刷屏（同一来源/同一产品多条灌水）

> 关键：软文里的信息（如"Pot 已停更"）仍保留在候选里，但**用于结论前必须交叉验证**。

---

## 四、加权总分与分档

```
总分 = (相关性×0.40 + 可信度×0.25 + 信息量×0.20 + 传播×0.15) × (软文? 0.4 : 1.0)
```

按总分排序后，映射为三档（用于后续标注，不用于硬删）：

| 档位 | 总分区间（示意） | 含义 |
|---|---|---|
| 保留 | ≥ 0.65 | 高相关 + 可信 + 有信息量 |
| 降权 | 0.40 ~ 0.65 | 软文 / 相关性弱 / 单一来源 |
| 存疑 | < 0.40 | 单一来源且无法交叉验证，标「⚠️ 存疑」 |

> 阈值（0.65 / 0.40）为初版经验值，后续用真实数据跑几轮后校准。

---

## 五、输出

按总分降序，取 **top 20~30 条** 作为「可信素材池」，每条带：
- 来源锚点（作者 + 赞同数 + 权威等级 + 原文链接）
- 总分 + 档位标记（保留/降权/存疑）

## 七、待校准项（后续迭代）

- [ ] 四个维度权重是否要微调（当前 40/25/20/15）
- [ ] 软文惩罚系数 ×0.4 是否合适
- [ ] 分档阈值 0.65 / 0.40 是否合适
- [ ] 传播分的对数压缩底数（log10(1000+1)）是否合适
- [ ] LLM 打分的一致性（同一批内容多次打分是否稳定）
